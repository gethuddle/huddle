**Evidence: source confirmed by two independent inspections; no live venue draft created.** Fixture planning exposes “Save batch as drafts,” then only “Open calendar.” Calendar/Events rows lead to detail, with no rendered editor or publish action. `savePrivateEventAction` and `saveVenueEventAction` have no non-test application callers. ### F02 · P1 — Handle-less reporters break moderation parsing

`features/moderation/queries.ts:32` requires a string handle. The reporting contract permits verified accounts without a Fan handle, and retained reporters may erase their handles. The SQL projection returns the nullable handle unchanged. A valid returned row then throws before the queue renders. An actual-schema, read-only probe reproduced `reporter_handle: invalid_type`; no live report was created.

The affected queue page fails as a unit; this is not a claim every page fails simultaneously. The appeals projection has the same non-null assumption for `appellant_handle`. SQL reference: `supabase/migrations/20260828190000_moderation_security_accessibility.sql:1054`. Test venue-only and erased reporters/appellants with an explicit neutral identity fallback, without recovering deleted identity.

### F03 · P1 — Private attendees lose the event page at kickoff

### F16 · P2 — Ask silently ignores or partially parses date language

**Live and local reproduction.** On 4 September, “Where can I watch Liverpool tonight?” returned the filter summary **“4–18 Sep · Liverpool FC”**. The single result happened to be tonight, but the actual search range was fourteen days wider than requested.

`features/assisted-discovery/service.ts:140` always supplies the raw query to `resolveIntentDateRange`. In `date-range.ts:48–54`, an unrecognized phrase defaults to today plus fourteen days, even if the model supplied a correct `temporal=today`. `query-date.ts:207–225,284–292` has neither a rule nor an unresolved-date guard for tonight, and its first-match rules partially consume some compound expressions.

Local checks used the actual TypeScript parser/formatter modules with a fixed Israel date, without additional provider calls:

| Phrase                   | Actual resolved dates | Problem                                    |
| ------------------------ | --------------------- | ------------------------------------------ |
| tonight / this evening   | 4–18 Sep              | Explicit intent treated as absent          |
| yesterday                | 4–18 Sep              | Past intent silently becomes future search |
| this week / next weekend | 4–18 Sep              | Explicit period ignored                    |
| day after tomorrow       | 5 Sep                 | `tomorrow` consumed before compound phrase |
| from Friday to Sunday    | 4 Sep only            | First weekday consumes the range           |
| last Friday              | 4 Sep                 | `last` qualifier ignored                   |

Today, tomorrow, this weekend, next week, supported weekday expressions, numeric “in 2 days,” and ISO/named explicit ranges passed those local checks. Support common complete expressions deterministically, and ask for clarification when a detected date expression is unsupported or ambiguous; do not silently broaden it. Add service-level tests with raw query supplied, not only enum-only resolver tests.

The current contract explicitly requires date-like intent to resolve or clarify: `docs/HUDDLE-IMPLEMENTATION-SPEC.md:856`.

## Remaining verification limitations

Live happy-path browsing cannot certify private-address revocation, race conditions, failed renewal, provider outage, email delivery, or irreversible account erasure. Those need deterministic isolated browser/database tests and separately scoped hosted checks. The current production checklist also contains historical entries that predate the latest migration/deployment evidence; final documentation must be reconciled rather than treating every old unchecked item as a current deployment defect.

The current user-reported persistent Explore workspace-switch symptom remains unresolved rather than disproved. The audit did not test every account role, historical row shape, browser/version, geographic network, or concurrent transition. No load test, penetration test, or formal security certification was performed. Passing 1,308 tests is useful regression evidence, but the direct-URL and fabricated-state examples above show why that count alone cannot establish submission readiness.
